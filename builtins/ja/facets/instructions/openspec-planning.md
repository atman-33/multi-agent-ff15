# Spec Planning — 手順指示

## 手順

1. **依頼内容を理解する**
   - User の元の依頼を注意深く読む
   - 中核となる目的、成功条件、制約を特定する
   - 新機能、バグ修正、リファクタリング、その他どの変更種別かを判断する

2. **User と要件を明確化する**
   - 要件が曖昧なら User に確認する
   - 自分の理解を提示し、進める前に確認を取る
   - 漠然とした質問ではなく、具体的な質問を使う

3. **Spec Plan を作成する**
   - `.opencode/command/opsx-ff.md` の手順に従って実行する。

## 重要ルール

- 実装を始めてはならない。ここでは計画のみを行う。
- 成果物は計画そのもの。完全で実行可能でなければならない。
- 判断に迷ったら User に確認する。推測で進めない。

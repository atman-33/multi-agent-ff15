# Implement — 手順指示

## 手順

1. **Spec Plan を読む**
   - 前の movement の spec plan を丁寧に確認する
   - スコープ、影響ファイル、実装方針、受け入れ条件を理解する
   - 技術的な blocker が見つからない限り、計画から逸脱しない

2. **準備する**
   - 影響範囲にある既存コードを確認する
   - 踏襲すべき既存パターンを見つける
   - テスト基盤が利用可能であることを確認する

3. **実装する**
   - 計画に従って本番品質のコードを書く
   - 命名、ファイル構造、パターンについて project の規約に従う
   - 実装と同時にテストを書く、または更新する
   - 一度に一つの関心事だけを扱う、原子的で段階的な変更にする

4. **自己検証する**
   - 型チェックを実行し、すべてのエラーを解消する
   - lint を実行し、すべての警告を解消する
   - テストを実行し、既存分も新規分も含めてすべて通す
   - 意図しない変更がないか自分の diff を見直す

5. **報告する**
   - 実装した内容を要約する
   - 作成または変更したファイルを列挙する
   - 計画からの逸脱があれば、その理由付きで記載する
   - 適切なステータスタグを出力する

## 重要ルール

- spec plan に従うこと。依頼されていない機能は追加しない。
- 計画が不可能または誤っている場合は、説明付きで abort のステータスタグを出力する。
- 完了報告の前に、必ずすべてのテストを通すこと。

# Refactor — 手順指示

## 手順

1. **実装内容を確認する**
   - 前の movement の実装出力を読む
   - 何が作られ、どのファイルが変更されたかを把握する
   - リファクタリング対象の範囲を特定する（この operation で触れたファイルのみ）

2. **単純化の観点で分析する**
   - コードの複雑性が高い箇所を見つける（長い関数、深いネスト、重複パターン）
   - デッドコード、未使用 import、不必要な抽象化がないか確認する
   - 明確さを高める命名改善の余地を探す
   - 体系的に単純化するために `code-simplifier` skill の考え方を使う

3. **リファクタリングを適用する**
   - 一度に一つの焦点化した改善だけを行う
   - 各変更後にテストを実行し、振る舞いが維持されていることを確認する
   - 優先順位は、デッドコード削除 > 重複排除 > 複雑性低減 > 命名改善 とする

4. **検証する**
   - 既存テストがすべて通ること
   - 型チェックが通ること
   - 振る舞いの変更が入っていないこと

5. **報告する**
   - 適用したリファクタリングを要約する（各項目の before/after を含む）
   - リファクタリング不要なら、すでにコードが十分きれいであると報告する
   - 適切なステータスタグを出力する

## 重要ルール

- 振る舞いの維持は絶対条件。変更の危険があるならそのリファクタリングは行わない。
- リファクタリングするのは、この operation の変更範囲に含まれるコードだけにする。
- すでにコードがきれいで構造化されているなら、"no changes needed" と報告してよい。

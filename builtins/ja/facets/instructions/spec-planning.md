# Spec Planning — 手順指示

## 手順

1. **依頼内容を理解する**
   - Crystal の元の依頼を注意深く読む
   - 中核となる目的、成功条件、制約を特定する
   - 新機能、バグ修正、リファクタリング、その他どの変更種別かを判断する

2. **コードベースを調査する**
   - 関連するコードベースの領域を調べる
   - 既存のパターン、規約、依存関係を把握する
   - 影響を受けるファイルやモジュールを洗い出す

3. **Crystal と要件を明確化する**
   - 要件が曖昧なら Crystal に確認する
   - 自分の理解を提示し、進める前に確認を取る
   - 漠然とした質問ではなく、具体的な質問を使う

4. **Spec Plan を作成する**
   - output-contract の形式に従って構造化された計画を書く
   - タスク要約、スコープ分析、実装方針、影響ファイル、リスク評価を含める
   - 追加確認なしでも別のエージェントが実装できるだけの具体性を持たせる

5. **ステータスタグを出力する**
   - 仕様が明確で承認済みなら、適切なステータスタグを出力する
   - 要件を明確化できない場合は、abort のステータスタグを出力する

## 重要ルール

- 実装を始めてはならない。ここでは計画のみを行う。
- 成果物は計画そのもの。完全で実行可能でなければならない。
- 判断に迷ったら Crystal に確認する。推測で進めない。
